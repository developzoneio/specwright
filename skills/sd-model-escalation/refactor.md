Read `SKILL.md` first: the ladder, the invariants, how the override is applied, the precedence
rules and the logging contract live there and are not restated here. Why each row exists is in
`rationale.md`, which no workflow reads at runtime.

## Decision points

**`paths.layers` empty.** When `paths.layers` is `[]`, only the file clause of `ESC-REF-04` is
evaluated.

**Per-task decision.** `ESC-REF-05` / `ESC-REF-05b` are decided once per task, when the task is
first invoked, and that decision covers the task's re-invocations in the same pass (a scope
revert, a failing test, constitution feedback, a red-batch fix) - one line per task, not per
retry. The next task starts at the default again (invariant 3). A task regenerated by Gate
Re-plan is a new task block and is decided afresh. Tasks of one batch run in parallel; each is
decided on its own.

**Phase 3 keeps the default.** The characterization-test calls pin current behavior and read no
task block, so no row applies to them.
